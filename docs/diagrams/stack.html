What VHD stands on, and what breaks when it moves

Most of the stack is ordinary and replaceable. The risk sits in one chain: the game, SteamCMD and BepInEx, none of which VHD controls and one of which changes without notice. This page maps every dependency, how it arrives in an install, and how far a change in it reaches.

What VHD will not depend on

  • A game file inside any image or release. The server downloads at first start; the build fetches what it needs and discards it.
  • An unpinned third party. Every image pins its base and its packages, and a change reaches installs only through a release.
  • An outside service for the game to run. Chat service, LLM provider and sign-in are optional; Steam is needed only to install and update.
  • Shared infrastructure outside the install, such as a central database, log pipeline or alerting. Each is a bring-your-own setting.
