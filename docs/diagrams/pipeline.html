ValhallowedRelease pipeline

From a commit to every install

Every change reaches consumers through the same gates and the same registry. CI never deploys to an install; installs pull released artifacts, and a release is exactly the images its candidate was.

    What the pipeline will not do

    • Deploy to an install. The server manager applies a new version with vhd apply, and a game-server restart waits while players are online unless the server manager confirms it.
    • Rebuild on promotion. A release is the same image digests its candidate was.
    • Ship game files. The dedicated server downloads at first start, and the game assemblies used for the build are fetched in CI and discarded.
    • Take a hand-built hot fix. A fix is a commit and passes the same gates.
    • Give any consumer its own channel or tag. The maintainers' own installs follow the release channel too.

    Ground rules behind this page: G12 build once, promote by tag; G16 VHD’s own game runtime image; G17 one repo.
