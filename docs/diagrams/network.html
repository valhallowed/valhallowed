What an install exposes, and to whom

An install opens as little as it can: the game ports for each world, the web map when it is on, and nothing else beyond the host. Every port and address on this page is a default; the manifest can change any of them, and reconcile rejects a clash. Whether an open port reaches the internet is up to the host's network: behind a home router it takes a port forward, and on a server with its own public address it is public unless a firewall closes it.

Exposure by profile

Exposing the web map directly

A server manager can open the game ports and the web map's port to the internet (a port forward on a home router, or a firewall rule on a server with its own public address) and give players http://<public IP>:8456. Steam sign-in works there: the player's browser goes to Steam's own HTTPS page and comes back to the address the manifest names as web_map.public_url, and the web map confirms the result with Steam directly. Players see the same flow as behind TLS. What changes is around that flow.

Direct exposure gives players the normal experience, with a weaker session and a more fragile address. The control plane says both in status when web_map.public_url is plain HTTP. Bundled TLS (O12) closes the gap without a domain: Let's Encrypt has issued six-day certificates for bare IP addresses since January 2026, renewed automatically, provided port 80 or 443 reaches the install for the challenge.

What an install never exposes

  • The database or any data-layer service on a host port.
  • The admin console beyond loopback, unless the manifest opens it.
  • Plain HTTP without saying so. Status warns whenever sessions travel unencrypted.
  • Calls home. No install talks to valhallowed.com or to the VHD project.
  • A fixed port. Every port above is a default the manifest can change.

Open decisions behind this page: O3 worlds per install, O6 manifest format (setting names are illustrative), O12 TLS for a public web map.
